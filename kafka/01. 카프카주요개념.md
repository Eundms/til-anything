# 용어 
## Topic(토픽) & Partition(파티션) & Offset(오프셋)
- 토픽 : 메시지 분류 카테고리 
- 파티션 : 토픽 내 병렬처리를 위해 나누는 기준
  - 메시지들이 여러 파티션 들 중에 한 곳에 immutable으로 append된다 
  - 하나의 파티션 내에서는 FIFO지만 여러 파티션 간에서는 보장되지 않는다 
    - 메시지 간 순서가 보장되어야 하는 경우 하나의 파티션으로만 가도록 producer 쪽에서 설정을 해야 한다
  - 메시지 보관 retention 기간이 있다 
- Offset : 파티션 안 저장된 메시지들의 순서 (0부터 시작, 64bit)

## Producer & Consumer
- Producer : 이벤트(메시지)를 토픽에 저장하는 역할
  - 어떤 파티션에 저장되어야 하는지를 결정
- Consumer : 토픽에 저장된 이벤트를 소비하여 목적에 맞게 처리하는 역할  
  - 같은 그룹에 속한 컨슈머들은 파티션들을 나누어 맡아 메시지를 처리한다 
  - 컨슈머 그룹 단위로 오프셋을 통해 어디까지 소비했는지 추적한다
  - 파티션 수보다 컨슈머가 더 많으면 노는 컨슈머가 발생한다 
  - 같은 topic도 다른 consumer group은 독립적으로 consume할 수 있다  
  - 모든 consumer는 반드시 단 하나의 consumer group에 속해야 한다 

## Event Message Record (같은 대상, 다른 강조 관점)
- Event : source application 에서 발생한 일 혹은 사실임을 강조 
- Message : producer에서 consumer로 전달된다는 것을 강조 
- Record : 카프카에 저장되는 데이터 그 자체 

## Log Segment
- Log : 하나의 파티션에 순서대로 append되는 immutable한 메시지 흐름
- Segment : Log를 실제로 저장하기 위해 여러 개의 파일로 나눈 단위 
  - Segment 파일 구성 : .log .index .timeindex 이 세 개의 파일이 하나의 segment 
  - 일정 크기나 시간 단위로 관리 
  - active segment만 append 가능 

## Replication Leader Follower ISR
- Replication : 각 `partition` 데이터를 여러 브로커에 복제하여 일부 브로커에 문제가 생겨도 메시지 유실없이 정상적으로 kafka가 동작하도록 하는 기능

- Leader : partition에 produce/consume 요청을 처리하는 브로커
  - 한 partition당 하나만 존재 
- Follower : Leader로부터 partition을 복제해서 저장하고 있는 브로커 

- Replica : partition의 원본과 복제본을 가지고 있는 브로커들 전체

- ISR(In-Sync Replicas) : 복제가 잘 되고 있어서 Leader와 동기화 상태인 replicas
  - `Leader 장애 시 여기서 새로운 Leader 선출`

- replication-factor : topic 생성할 때 원본 포함 복제본 몇 개 둘 것인지 설정
  - 보통 3을 추천하며 broker 수 보다 더 클 순 없다 

## Zookeeper -> KRaft
- Zookeeper : Kafaka라는 분산 시스템을 안정적이고 일관성 있게 유지하는 데 필요한 메타데이터를 관리하고 조정 작업을 수행 
- KRaft : Zookeeper 역할을 Kafka cluster 내부에서 일부 노드들이 수행

> 파티션 단위로 데이터가 Replication된다
